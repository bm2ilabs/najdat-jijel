# هبة الجزائر (HabaDZ)

**منصة جزائرية لتنسيق المساعدات والإغاثة الميدانية**  
الموقع الحي: [https://habadz.life](https://habadz.life)

> **شعار المنصة:** *ننسّق التضامن، ونوصل المساعدة لمن يحتاجها.*  
> مبادرة رقمية مستقلة لتنسيق التضامن — غير حكومية وغير تابعة لأي جهة رسمية، هدفها تنظيم المساعدات العينية وتوجيهها للمناطق والأسر الأكثر تضررًا ومنع الفوضى والتكرار والهدر.

المنصة ثنائية اللغة (**العربية / الفرنسية**) — يمكن للزائر تبديل اللغة من شريط التنقل، مع دعم كامل للاتجاهين RTL/LTR.

---

## 📌 عن المنصة والفكرة الأساسية

في حالات الطوارئ والكوارث الطبيعية، يتدفق تضامن واسع من المواطنين والجمعيات، لكن غياب التنسيق الميداني يؤدي غالبًا إلى تراكم مواد معينة في مناطق يسهل الوصول إليها، ونقص حاد في مناطق أخرى نائية، أو إرسال مواد لا توافق الاحتياج الفعلي.

**الفكرة الأساسية لمنصة هبة الجزائر:**  
1. **اعرف ما هو مطلوب فعليًا:** حصر دقيق للاحتياجات الميدانية ذات الأولوية وتحديثها باستمرار.
2. **وجّه مساعدتك بدقة:** مطابقة تبرعات المواطنين مع النقص الحقيقي واقتراح أقرب نقاط التجميع ومراكز الاستقبال.
3. **تتبع المسار والشفافية:** تسجيل وصول الإعانات وتوزيعها على المتضررين لضمان وصول المساعدات لمستحقيها دون هدر.

الحملة النشطة حاليًا: **حرائق الشمال الشرقي 2026** — تغطي ولايات **جيجل، بجاية، ميلة، سكيكدة**.  
صُممت بنية قاعدة البيانات لتكون مرنة وقائمة على مفهوم "الحملات" (`campaigns`)، مما يسمح بإطلاق حملات استجابة لطوارئ أخرى (فيضانات، زلازل، ولايات أخرى) دون إعادة هيكلة النظام.

## 🛠️ التقنيات المستخدمة

| الطبقة | التقنية | التفاصيل |
|---|---|---|
| **الإطار البرمجي** | Next.js 16 (App Router) + TypeScript | بنية معتمدة على Server Components و Server Actions |
| **قاعدة البيانات والخدمات** | Supabase | PostgreSQL + Auth + Row Level Security (RLS) + Storage + Database Functions/Triggers |
| **واجهة المستخدم والتصميم** | Tailwind CSS v4 + shadcn/ui | نظام تصميم OKLCH مهيأ بالكامل للغة العربية والاتجاه من اليمين لليسار (RTL) |
| **الخرائط** | MapLibre GL + OpenStreetMap | خرائط تفاعلية مفتوحة المصدر بدون الحاجة لأي مفاتيح أو اشتراكات مدفوعة |
| **النماذج والتحقق** | React Hook Form + Zod | تحقق صارم من صحة البيانات من جانب العميل والخادم |
| **الأيقونات والخطوط** | Lucide Icons + Vazirmatn | أيقونات خفيفة وخط طباعي عربي واضح وقابل للقراءة |
| **تعدد اللغات (i18n)** | نظام قواميس مخصص (`src/i18n/`) | عربي/فرنسي عبر ملفات `messages/ar.ts` و`messages/fr.ts`، مع فحص TypeScript يمنع نسيان ترجمة أي مفتاح جديد |

## 🔒 قرارات التصميم والأمان (RLS)

- **أمان مستوى الصف (Row Level Security):** هو خط الدفاع الأساسي في المنصة. لا يُسمح للزوار غير المسجلين (`anon`) بالاطلاع على البيانات الحساسة (أسماء المتضررين، أرقام الهواتف الشخصية، تفاصيل الاحتياجات الخاصة).
- **نماذج الإدخال العام:** التسجيل العام (طلب مساعدة، تسجيل تبرع، عرض نقل، تطوع طبي) يستخدم الصلاحية العامة بموجب سياسة `INSERT-only` بدون منح صلاحية القراءة المباشرة على الجدول.
- **عرض المراكز بأمان:** عرض نقاط التجميع ومراكز الاستقبال يمر عبر دوال RPC مخصصة تخفي أرقام الهواتف والبيانات الخاصة ما لم يحدد المشرفون إمكانية عرضها للعامة.
- **إدارة المخزون عبر سجل المعاملات:** المخزون ليس رقمًا جامدًا يُعدل يدويًا، بل يتم عبر حركات وارد/صادر/تسوية (`inventory_transactions`) مع تحديث آلي للمستويات عبر Database Triggers.
- **التوليد الآلي للاحتياجات:** عند انخفاض مخزون مادة أساسية في مركز استقبال عن الحد الأدنى (`min_threshold`)، يتم توليد سجل احتياج تلقائيًا، ويُغلق آليًا عند استلام شحنات كافية.
- **خوارزميات المطابقة:** منطق حسابي صريح ودقيق في TypeScript يعتمد على القرب الجغرافي ونوع الفئة ومستوى العجز، بعيدًا عن أي غموض أو تكهنات.
- **حماية نقاط الاستقبال الخارجية (Webhooks):** `/api/news/sync` و`/api/news/webhook` يتطلبان مفتاحًا سريًا (`WEBHOOK_SECRET` أو `CRON_SECRET`) عبر ترويسة `Authorization: Bearer` قبل معالجة أي طلب.
